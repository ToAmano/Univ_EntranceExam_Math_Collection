## N1. 場合分け

### N1.1 `dcases` を使う
- 場合分けは mathtools の `dcases` で書く。`cases` は使わない。
  - `cases` の中は文字が小さく組まれるため、以前は `\displaystyle` を補っていた。`dcases` なら中身が最初からディスプレイスタイルになり、`\displaystyle` は要らない。
  - 2列目（条件）を地の文として書く場合は `dcases*` を使う。
  - 右側を括弧でくくる場合は `drcases`（`drcases*`）を使う。
- lint で検出できる：`\begin{cases}` をエラーにする（未実装）。
- 既存原稿の `cases`（約1150か所）を移行するかは別作業として判断する。

## N2. 組合せ・二項係数

### N2.1 `\binom` を使わない
- 組合せの数・二項係数は、高校の教科書と同じ `{}_nC_k` の形で書く（例：`{}_6C_2`、`{}_{n}C_{k}`）。
- `\binom`・`\dbinom`・`\tbinom` は使わない。
- lint で検出できる：`\binom` 系のコマンドをエラーにする（未実装）。
- `C` を立体（`\mathrm{C}`）にするかは TODO T3 で決める。

## N3. 証明・解答の終わり

### N3.1 数式の外の文末に `\qed` と書く
- 証明や解答の終わりは、最後の文の末尾に `\qed` と書く（例：`よって題意は示された．\qed`）。amsthm の `\qed` は記号を行の右端へ自動で寄せ、記号だけが次の行に送られるのも防ぐので、`\hfill` は要らない。
- 記号はプリアンブルの `\renewcommand{\qedsymbol}{\ensuremath{\blacksquare}}` で黒塗りの ■ に統一する。原稿では記号を直接書かない（`$\blacksquare$`・`$\Box$`・文末の `$\square$` は使わない）。
- 別行立ての数式で終わるときも、数式の中には書かず、数式の後の文の末尾に置く（例：`\end{align}` の次の行の `である．\qed`）。数式の中の `\qed` は右に寄らない。
- `proof` 環境は末尾に自動で記号を付けるので、`\end{proof}` の直前には書かない。
- 四角形を表す `\square ABCD` は対象外。
- Web では、文末の `\qed` を右端に寄せた ■ に変換する（`tex_to_md.py` の `convert_text_qed`）。
- lint：`check_qed_mark`（2026-11-13 追加）。

## N4. 句読点

### N4.1 和文の句読点は全角の「．」「，」
- 本文の句読点は全角の「．」「，」に統一する（例：`題意から，$x=1$ である．`）。
- 「。」「、」と、和文に接する半角の「,」「.」（`である.`、`から,`、`以下, `）は使わない。全角の句読点は後ろの空きを含むので、直後に空白を入れない。
- 数式の中の「,」「.」（`$a, b$`、`$1.5$`）、点の連続（`...`）、コメントは対象外。
- lint：`check_punctuation`。`--fix`（pre-commit）で全角に直す。

### T1. ベクトルの成分表示を `\mqty` で書く（physics パッケージ）
保留の理由と、採用するときに必要な作業：
- `tex_to_md.py` の `\mqty(...)` の変換が正規表現 `\mqty\((.*?)\)` のため、中に括弧があると最初の `)` で切れて Web 表示が崩れる。括弧の対応を数える処理に直す必要がある（既存例：`src/utokyo/kouki/2001/2/solution.tex` の `\mqty(2(\sqrt{2}+1) \\ 0)`）。
- プリアンブルの physics の読み込みが `\IfFileExists` による任意読み込みなので、必須にする。
- physics を読み込むと siunitx の `\qty` が定義されない（T2 と干渉する）。
- 公開スキルでは physics への依存に賛否があるため、公開版の既定は `pmatrix` にし、`\mqty` はこのリポジトリの規約（`local/`）とする案。

### T2. 単位を siunitx で書く
保留の理由と、採用するときに必要な作業：
- physics と併用すると siunitx の `\qty{3}{\meter}` はエラーになる（2026-11-12 に確認。siunitx が「physics を検出したので `\qty` を定義しない」と警告する）。使うのは `\SI{60}{km/h}`・`\unit{km/h}`・`\num{...}` に限り、`\qty` は禁止する案。
- `main.tex` のプリアンブル（`scratch/generate_main_tex.py`）と、Web 用 SVG のコンパイル用プリアンブル（`tex_to_md.py`）に siunitx を追加する。
- MathJax には siunitx がないので、`tex_to_md.py` で `\SI{60}{km/h}` を `60\,\mathrm{km/h}` のように展開する。地の文の `\SI` も対象にする。
- 円・分・個などの日本語の単位は siunitx の対象外とし、`L/分` のような混ざった単位の扱いを決める。
- `\num{12345}` は既定で「12 345」と桁区切りの空白が入るので、`group-digits=none` などの設定を決める。

### T3. 記号を立体（`\mathrm`）にするか
組合せの `C` と、図形の点の名前（`A`、`\triangle ABC` など）を、斜体のままにするか立体（`\mathrm{C}`、`\mathrm{A}`）にするかを、まとめて決める。
- 既存原稿は混在している。組合せは `{}_nC_k`（約280か所）と `{}_n\mathrm{C}_k`（約110か所）。点の名前も `$A$` と `$\mathrm{A}$` の両方がある。
- 決めたら、本文・図のラベル・caption で同じ書き方にそろえる（図の規約 §4.2 にも反映する）。
