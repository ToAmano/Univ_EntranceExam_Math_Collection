# 数式・記法の規約（下書き）

数式の書き方の規約の正本。節番号（§）で引けるようにしてある。
各節の「lint」は、機械で調べる検査の名前（`scripts/lint_tex.py` の関数名）。`--fix` と書いたものは機械的に直せる。lint の指摘の末尾には、この節番号が `[§N5.1]` の形で付く。
見出し・ファイルの構成など利用先固有の記法は `local/notation.md` にある。

## N1. 場合分け

### N1.1 `dcases` を使う
- 場合分けは mathtools の `dcases` で書く。`cases` は使わない。
  - `cases` の中は文字が小さく組まれるため、以前は `\displaystyle` を補っていた。`dcases` なら中身が最初からディスプレイスタイルになり、`\displaystyle` は要らない。
  - 2列目（条件）を地の文として書く場合は `dcases*` を使う。
  - 右側を括弧でくくる場合は `drcases`（`drcases*`）を使う。
- lint：`check_cases_env`（警告。既存原稿の移行を決めるまではエラーにしない）。
- 既存原稿の `cases`（約1150か所）を移行するかは別作業として判断する。移行するまでの間、`cases` を残す箇所では、中の分数などが小さく組まれないよう `\displaystyle` を補う（`\begin{cases}\displaystyle ...`）。

## N2. 組合せ・二項係数

### N2.1 `\binom` を使わない
- 組合せの数・二項係数は、高校の教科書と同じ `{}_nC_k` の形で書く（例：`{}_6C_2`、`{}_{n}C_{k}`）。
- `\binom`・`\dbinom`・`\tbinom` は使わない。
- lint：`check_binom`。
- `C` を立体（`\mathrm{C}`）にするかは TODO T3 で決める。

## N3. 証明・解答の終わり

### N3.1 数式の外の文末に `\qed` と書く
- 証明や解答の終わりは、最後の文の末尾に `\qed` と書く（例：`よって題意は示された．\qed`）。amsthm の `\qed` は記号を行の右端へ自動で寄せ、記号だけが次の行に送られるのも防ぐので、`\hfill` は要らない。
- 記号はプリアンブルの `\renewcommand{\qedsymbol}{\ensuremath{\blacksquare}}` で黒塗りの ■ に統一する。原稿では記号を直接書かない（`$\blacksquare$`・`$\Box$`・文末の `$\square$` は使わない）。
- 別行立ての数式で終わるときも、数式の中には書かず、数式の後の文の末尾に置く（例：`\end{align}` の次の行の `である．\qed`）。数式の中の `\qed` は右に寄らない。
- `proof` 環境は末尾に自動で記号を付けるので、`\end{proof}` の直前には書かない。
- 四角形を表す `\square ABCD` は対象外。
- Web では、文末の `\qed` を右端に寄せた ■ に変換する（`tex_to_md.py` の `convert_text_qed`）。
- lint：`check_qed_mark`（2026-11-13 追加）。

## N4. 句読点

### N4.1 和文の句読点は全角の「．」「，」
- 本文の句読点は全角の「．」「，」に統一する（例：`題意から，$x=1$ である．`）。
- 「。」「、」と、和文に接する半角の「,」「.」（`である.`、`から,`、`以下, `）は使わない。全角の句読点は後ろの空きを含むので、直後に空白を入れない。
- 数式の中の「,」「.」（`$a, b$`、`$1.5$`）、点の連続（`...`）、コメントは対象外。
- lint：`check_punctuation`。`--fix`（pre-commit）で全角に直す。

## N5. 別行立ての数式

### N5.1 `align` を使う
- 別行立ての数式は、1行だけでも `align` で書く。記法がそろい、あとから式変形を足すときに書き直さずに済む。
- `equation`・`equation*`・`align*`・`\[ ... \]`・`$$ ... $$` は使わない。
- 複数行の変形は `&=` で位置をそろえる。
- lint：`check_align_star`、`check_equation_env`、`check_display_math_brackets`、`check_display_math_dollars`（いずれも `--fix` で `align` に直す）。

### N5.2 途中の式番号をまとめる
- `&=` でつないで最後の結果だけに意味がある変形は、`split` で包んで式番号を1つにすることを検討する（`\begin{align}\begin{split} ... \end{split}\end{align}`）。または途中の行に `\notag` を付ける。
- `split` は1行に `&` を1つしか使えない。1行に複数の位置そろえが要る変形では、無理に `split` にせず、行ごとに番号の付く `align` のままでよい。

### N5.3 最後の行に `\\` を付けない
- `align` の最後の行の末尾に `\\`（`\\[2pt]` などを含む）を付けない。中身のない行ができ、PDF に空の式番号が出る。`\\` と `\end{align}` の間に `\label` や `\notag` しかない場合も同じ。
- lint：`check_trailing_align_break`（`--fix` で消す）。

### N5.4 長い行は改行する
- `=` を2つ以上含み、表示幅がおよそ80文字を超える行は、`\\` と `&=` で複数の行に分ける。`a=b=c=d=\cdots` を1行に並べると読みにくく、紙面からはみ出しやすい。
- 改行の位置は意味の切れ目で人が決める（括弧や `\left ... \right` の中で機械的に割ると壊れる）。
- lint：`check_long_align_lines`（警告。終了コードには影響しない）。

## N6. 分数・根号

### N6.1 分数は `\dfrac`
- 分数は `\frac` ではなく `\dfrac` で書く。`align` の中でも `\frac` は小さく組まれることがある。
- 例外：添字の位置（`_{...}`・`^{...}` の中）と、TikZ のノードのラベルでは `\frac` を使う。添字の位置では文字が縮小されるため、`\dfrac` だと縦に間延びする。積分の上下限や評価記号 `\Bigl[ \Bigr]_a^b` に限らず、`x^{\frac{1}{m}}` のような指数も含む。
  - 例：`\int_{\frac{a}{b}}^{b}`、`\Bigl[F(x)\Bigr]_{\frac{a}{b}}^{b}`、`x^{\frac{1}{m}}`
- lint：`check_frac_subscript_rule`（`--fix` で直す）。

### N6.2 引数は `{}` で囲む
- `\dfrac`・`\frac`・`\sqrt` の引数は必ず `{}` で囲む。`\sqrt2`・`\dfrac12` のような省略形は使わず、`\sqrt{2}`・`\dfrac{1}{2}` と書く。
- lint：`check_bare_args`（`--fix` で囲む）。

## N7. 括弧

### N7.1 大きい括弧は大きさを明示する
- 中身が分数や指数で背が高くなる括弧は、素の `( )`・`[ ]` のままにせず、`\Bigl( \Bigr)`・`\Bigl[ \Bigr]` などで大きさを明示する。迷ったら `\Bigl` 系を既定にする。
- `\left ... \right` の自動調整は式ごとに高さがまちまちになりやすい。複数の式で大きさをそろえたい場面では避ける。
- lint：なし（大きさの判断は目視）。

### N7.2 `\left` と `\right` を対にする
- 1つの `align` の中で、`\left` と `\right` の数を一致させる（片側だけなら `\left.`・`\right.` を使う）。数が合わないと、Web の MathJax では式全体が表示されない。
- lint：`check_left_right_balance`（`align` のブロック全体で数を比べる）。

### N7.3 丸括弧 `()` と角括弧 `[]` の対応を合わせる
- 数式（`align`・`equation`・`gather`・`multline`・`$...$` 等、`\text{...}` などのテキスト系引数を除く）の中に、`(` / `)` や `[` / `]` が片側だけ単体・不対で残らないようにする。`{}` と違い単体の `)` などは TeX コンパイルを通ってしまうため lint で検出する。
- 半開区間 `(a, b]`・`[a, b)` や開区間 `]a, b[` は開き括弧と閉じ括弧の合計が一致するため許容する。改行の余白指定 `\\[5pt]` や `\sqrt[n]{x}`・`\begin{array}[t]` などのオプション引数は対象外。
- lint：`check_math_brackets`。

### N7.4 本文の括弧・かぎ括弧の対応を合わせる
- 数式外の本文（`\caption{...}` や数式内の `\text{...}` 等を含む。TikZ・コメント・verbatim を除く）で、半角 `()`、全角 `（）`、かぎ括弧 `「」`・`『』` の開きと閉じを対応させる。片側の欠落や半角・全角の混在（`(...）` 等）を防ぐ。
- lint：`check_prose_brackets`。

## N8. ベクトル

### N8.1 矢印の下の文字数で使い分ける
- 1文字（英数字・ギリシャ文字・`\ell` など）：`\vec`（例：`\vec{a}`、`\vec{0}`、`\vec{\ell}`）
- 2文字以上（始点と終点を並べた表記など）：`\overrightarrow`（例：`\overrightarrow{AB}`、`\overrightarrow{P_1P_2}`）
- 添字やプライムの付く1文字のベクトルは、矢印を文字本体にだけかけるため、添字・プライムを外に出す（`\vec{a}_1`、`\vec{e}_k`、`\vec{b}'`）。`\vec{a_1}`・`\overrightarrow{a_1}` とは書かない。
- lint：`check_vector_notation`（`--fix` で直す）。

## N9. 辺の長さ

### N9.1 `|AB|` と書く
- 辺・線分の長さは `\overline{AB}` ではなく、絶対値の記号ではさんで `|AB|` と書く。原稿が `\overline{}` でも、TeX にするときに直す。
- lint：`check_overline_warning`（警告）。

## N10. 相互参照とラベル

### N10.1 参照は `\cref`
- 数式・図・表の参照は `\cref` に統一する（`\cref{eq:1}`、`\cref{fig:...}`、`\cref{tab:...}`）。`\eqref`・`\ref` は使わない。
- lint：`check_reference_commands`（`--fix` で `\cref` に直す）。

### N10.2 数式のラベルは `eq:1` 形式の連番
- 数式に付けるラベルは `eq:1`、`eq:2`、… の連番にする。`eq:hw_sum` のような名前付きのラベルは使わない。番号は答案の中で上から順に振る。
- 理由：答案ごとに連番なら、式を足したり入れ替えたりしたときに機械で振り直せる。名前を考える手間もない。
- 図・表のラベルは内容が分かる名前でよい（`fig:region_answer` など）。
- lint：`check_equation_references`（`--fix` で連番に振り直す）。

### N10.3 未定義のラベルを参照しない
- `\cref` で参照するラベルは、同じ答案（と、一緒に組む本文。`local/` 参照）の中で定義されていなければならない。
- lint：`check_equation_references`。

### N10.4 ラベルを重複させない
- 同じファイルの中で同じラベルを2回定義しない。重複すると `\cref` の参照先が後から定義された方になり、どちらを指すか分からなくなる。
- 複数の答案を1冊に束ねる場合も、各答案が自分の中の式だけを参照する書き方なら、ほかのファイルとラベル名が同じでも実害はない。
- lint：`check_duplicate_labels`。

## N11. 余白・改行の命令

### N11.1 本文で余白・改行の命令を使わない
- 本文では、余白や改行のためだけの命令を使わない。見出しの前後などの余白は、文書の側で一律に付ける。
  - 使わない：`\medskip`、`\bigskip`、`\smallskip`、`\vspace{...}`、`\hspace{...}`、`\hfill`、`\vfill`、`\noindent`、`\newline`、数式の外の `\quad`・`\qquad`
- 数式・図・表・TikZ の中（式と注記の間の `\quad`、図を並べる `\hfill` など）と、空欄の下線 `\underline{\hspace{...}}` は対象外。
- lint：`check_spacing_commands`。

## N12. 数式内の文字

### N12.1 数式の中に（`\text` などを除き）全角文字を入れない
- 数式（`align`・`equation`・`gather`・`multline`・`$...$` 等）の中に、`\text{...}`・`\mbox{...}`・`\mathrm{...}`・`\intertext{...}` 等を介さず直接全角文字（和文、全角の「，」「．」「（」「）」「　」、丸数字、`×`、`−`、`°` など）を書かない。
  - テキスト注記は `\text{...}` で囲む。乗算は `\times`、角度は `^\circ`、負号は半角 `-`、数式内のカンマは半角 `,` を使う。
- lint：`check_math_fullwidth`。

## N13. 日本語の誤字・表記

### N13.1 日本語の明らかな誤字・誤変換・助詞重複を書かない
- 数式外の本文（`\caption{...}` や数式内 `\text{...}` 等を含む）で、以下の機械的に判定できる誤りを避ける：
  - 助詞や語句の重複（`がが`・`をを`・`にに`・`へへ`・`からから`・`よりより`・`ためため`・`のでので`・`であるである`・`となるとなる`、`はは`・`のの` の誤打ち）
  - 句読点の重複（`，，`・`．．`・`，．`・`．，`・`,,`・`..`）および半角カタカナ
  - 数学答案で典型的な誤変換（`巣学的`→`数学的`、`単調現象`→`単調減少`、`軸並行`→`軸平行`、`線対象`/`対象性`→`対称`、`互いに疎`→`互いに素`、`積分整数`→`積分定数`、`背離法`→`背理法` 等）
- lint：`check_japanese_typos`。

### N13.2 本文中の英数字は半角を使う
- 本文中のアラビア数字・アルファベットは全角（`１`・`２`・`Ａ` 等）ではなく半角を使う。
- lint：`check_prose_fullwidth_alnum`（警告）。
