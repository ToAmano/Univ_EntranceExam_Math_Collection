# 数学答案の TeX 規約と検査

数学の答案・解答を TeX で書くときの規約と、その検査の手順。

- **規約の正本**は `references/` にある。全部を読まず、工程ごとに必要な節（§）だけを読む。
- **機械で調べられることは機械で調べる**（lint、式変形の検算、図だけの差分の確認）。
- **最後は必ず人の目で見る**。コンパイルが通っただけで完了にしない。PDF の全ページ（Web に出すなら SVG も）を表示して確かめる。

| `scripts/tex_references.py` | ラベル・参照の読み取りと正規化（lint が使う） | あり |

| `local/` | 利用先（リポジトリ）固有の規約・コマンド・手本 | `local/workflow.md`（検査・確認のコマンド）、`local/transcription.md`（文字起こしの手順）、`local/notation.md`（見出し・ファイル構成などの固有の記法）、`local/lint_local.py`（固有の lint の検査） |

具体的なコマンドやファイルの場所は `local/` にある。`references/` と `SKILL.md` には利用先に依存することを書かない。

規約どうし、または規約と利用先のリポジトリの指示（`AGENTS.md` など）が食い違う場合は、**リポジトリの指示を優先**し、食い違いを作業報告に書く。

## 工程

作業の種類に応じて、該当する工程だけを行う。各工程で「読むもの」の節を先に読んでから手を動かす。

### 0. 文字起こし（手書き原稿がある場合）
- **読むもの**：`references/transcription-rules.md`（全体）、`local/transcription.md`
- **要点**：
  - 原稿の解法・式の流れ・くだけた表現をそのまま起こす。別の解法に差し替えない（§TR1）。
  - 書き始める前に、原稿の全ページを洗い出す（§TR2.1）。
  - 原稿の誤りは直さず、`% 原稿ママ：` のコメントで示す（§TR4）。
  - 判読に迷った箇所は `% 判読：` のコメントで示す（§TR3.3）。
- この工程が終わったら、記法・図・表は以下の工程の規約に合わせる（§TR1.3）。

### 1. 何を示すかを決める
- 問題文（小問・条件・定義域）を読み、答案で示すこと・使う記号・場合分けを決める。
- 図を描くなら、何を読ませる図かを先に決める（figure §0.1）。

### 2. 書く（数式・記法）
- **読むもの**：`references/notation-rules.md`。利用先固有の記法（見出しやファイルの構成）は `local/notation.md`。
- **主な規則**：
  - 別行立ての数式は `align`、番号をまとめるときは `split` か `\notag`（§N5）。分数は `\dfrac`、添字の位置は `\frac`（§N6）。
  - 場合分けは `dcases`（§N1）、組合せは `{}_nC_k`（§N2）、ベクトルは `\vec`/`\overrightarrow`（§N8）、辺の長さは `|AB|`（§N9）。
  - 証明・解答の終わりは `\qed`（§N3）、句読点は「．」「，」（§N4）、本文で余白の命令を使わない（§N11）。
  - 参照は `\cref`、数式のラベルは `eq:1` 形式の連番（§N10）。

### 3. 図
- **読むもの**：`references/figure-rules.md`。
  - 新しく描く：§0〜§6、付録 A の雛形
  - 立体：§7
  - 遷移図：§8、付録 C
  - 概要図：§9
- 描いたあとは、§10（幾何の整合）と §11（確認手順）を必ず行う。
- **図だけを直すよう指示された場合**は、figure §12 に従う。図のブロック以外を一切変えず、図以外に差分がないことを `scripts/check_figure_only_diff.py <file>` で確かめるまで完了にしない（`PASS` が出るまで）。

### 4. 表
- **読むもの**：`references/table-rules.md`。
  - `table` の中に入れ、`\caption` を付ける（§TB1）。
  - 増減表は符号と矢印を対応させ、端点の値と極限の書き方をそろえる。凹凸は専用の4つの矢印を使い、回した矢印を流用しない（§TB2）。

### 5. 機械で検査する
コマンドは `local/workflow.md`（W1〜W3）。

1. **lint**：記法・図・表の規約のうち機械で判定できるものを調べる。`scripts/lint_tex.py <file>` で汎用の検査を行い、利用先固有の検査は `--rules <module.py>` で足す（`PROFILE` を定義したモジュール。`local/lint_local.py` が例）。`--diff` で機械的な修正を確かめてから `--fix` で書き込む。
2. **式変形の検算**：`scripts/check_math_steps.py <file>`
   - 出てくるのは誤りの「候補」。確度 A（数値どうし）は誤りの可能性が高く、確度 B は文字の意味や前提しだいで誤検出もある。
   - 指摘は必ず式と原稿を見て確かめる。検算が通ったことは正しさの証明ではない。
3. **図だけの変更なら**、図以外に差分がないことの確認（figure §12）。

### 6. 目で確かめる
- 一時ディレクトリに出力してコンパイルし、PDF の**全ページ**を画像にして見る（コマンドは `local/workflow.md` の W4）。
- 図は figure §11 の「見るところ」に沿って、ラベルの重なり・切れ・縮小時の読みやすさ・幾何の整合を確かめる。必要な部分は高解像度で切り出して拡大する。
- Web などに変換して公開する場合は、変換後の表示も見る（W5）。

## いつも守ること
- **頼まれた範囲だけを変える**。ついでの書き換え（数式環境の移行、見出しの統一、参照の修正など）をしない。気づいた点は報告するか、Issue に記録する。
- **1ページに収めるための圧縮をしない**（figure §0.3）。式を詰めたり図を縮めたりしない。
- **結果をそのまま報告する**。検査が失敗した、確認を省いた、判読できなかった、といったことは隠さずに書く。
- 一時ファイル（描画した画像、コンパイル成果物）をリポジトリに残さない。
