# 数式ラベルと参照

各問の `solution.tex` では，数式ラベルを登場順に `\label{eq:1}`，`\label{eq:2}`，… と付ける．同じ問で同じラベルを再利用しない．参照は `\cref{eq:1}`，`\ref{eq:1}`，`\eqref{eq:1}`（複数なら `\cref{eq:1,eq:2}`）と書く．

`scratch/lint_latex_style.py` は，数式ラベルの形式，同じ問題内での重複，未定義参照を検査する．`--fix` は一意に対応する数式ラベルを登場順に振り直し，対応する参照も更新する．重複した旧ラベルは参照先が曖昧なので自動修正しない．検査対象は各問の `solution.tex` と，そこから参照する同じ問の `problem.tex` のラベルである．既存の `% lint-skip:` は文章・図の書式検査だけを省略し，ラベルと参照の検査は省略しない．pre-commit と CI は変更された `solution.tex` を検査する．

統合PDFでは別の問の `eq:1` 同士が衝突する．PDFを作る際は `python3 scratch/build_pdf_book.py titech/zenki --output /tmp/titech_zenki.pdf` を使う．このコマンドは一時的なコピーでラベルと参照に `titech:zenki:2004:2:eq:1` のような問固有のprefixを付けてからコンパイルする．図・表のラベルにも同じ処理を行う．原稿中のラベルは変更しない．GitHub Actions の PDF ビルドもこのコマンドを使用する．

既存原稿の一括移行では216ファイルを更新した．当初保留した6ファイルは原稿側の参照誤記が修正された後に移行した．

原稿側の修正後，2026-10-22に全 `solution.tex` のラベル形式・重複・未定義参照を再走査し，エラー0件を確認した．新たな解答を追加・修正した際も同じ検査を行う．
