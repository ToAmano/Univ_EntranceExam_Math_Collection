# 問題形式（証明・求値）の分類

`data/problem_types.yaml` が統計ページの分類マスターです。分野タグと同じ `大学/日程/年度/問題番号` をキーにし、各問題を1行で管理します。

```yaml
titech/zenki/2001/1: value
```

- `proof`: 証明の要求があり、求値の要求はない問題
- `value`: 求値・計算・条件の決定・大小比較など、答えを特定する要求があり、証明の要求はない問題
- `mixed`: 一つの大問に証明と求値の両方がある
- `other`: 図示のみ、答案の加筆訂正など、上記に収まらない問い
- `dual`: 新課程と旧課程で別の問題を併記したもの
- `unclassified`: 判定保留

最初の1115問は問題文中の動詞を使った機械的な推定値です。その後、当初の判定保留113問を問題文と照合し、古い表記・「問に答えよ」の誤検出など、見つかった誤判定を修正しました。修正行には `# reviewed` を付けています。残りは全件を目視確認した分類ではありません。誤判定を見つけたらマスターの該当行を編集してください。統計生成時に問題文から再判定して上書きすることはありません。

新旧課程併記の15問は一つの問題IDに別の出題が入っているため、証明・求値の割合の分母から除きます。`other` は分母に含め、`unclassified` は除きます。これにより「判定保留」と実際に別形式の問いを区別します。

新しい問題を追加したら、`python3 scratch/generate_reasoning_metrics.py --suggest-missing` で未登録問題の候補を確認し、マスターに1行追加します。候補は問題文を読んで判断してください。通常の生成コマンドはマスターと問題ファイルのIDが一致しない場合に失敗します。
